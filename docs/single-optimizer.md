# 单人配装算法

实现入口在 [algorithm.rs](../mona_wasm/src/applications/optimize_artifacts/algorithm.rs)。本轮只调整单人配装搜索与结果管理，不重构多人配装，也不改变游戏倍率或属性图求解语义。

## 路径与兼容

| 持久化名称 | 页面名称 / 用途 | 行为 |
| --- | --- | --- |
| `AStar` | 快速配装，默认 | 按部位、主词条、套装分组，以虚拟的「超级圣遗物」估分剪枝 |
| `Naive` | 完整枚举 | 完整遍历输入候选域，只提前排除确定无法满足套装数量的分支 |
| `Heuristic` | 旧预设兼容入口 | 复用分组剪枝，停止调用旧候选预筛选 |

保留以上序列化名称，不迁移预设或圣遗物 ID。旧 `AStarCutoff` 类型现在转发到真正的枚举实现，避免「纯枚举」仍按估值剪枝。旧预筛选依赖很多目标尚未实现的 `get_target_function_opt_config`，还可能删除同分候选或清空部位，因此从这些单人优化路径移除。

前端通过单独的显示选项把 `Heuristic` 映射为快速配装，页面状态和保存预设仍保留原标识，直到用户主动更换算法。缺失或不识别的算法值只在使用时回退 `AStar`，不在导入或读取 Store 时批量改写文件。预设版本保持 4，旧版本 3 的升级流程、账号存储键、文件备份格式与计算器状态格式均不变；多人配装的转换入口未调整。缓存优化没有新增持久化字段。

旧实现已另行完整恢复到 [legacy](../mona_wasm/src/applications/optimize_artifacts/algorithms/legacy/mod.rs)。六个文件以 `e9543ad1` 为基线，仅调整内部模块路径，保留原有行为和已知缺陷；通过 `optimizer-legacy` feature 编译。它们可独立运行作对照，默认网页包不包含这些模块，也不调用它们。历史优化器仍连接当前计算核心，因此基准测的是同一核心下的算法差异，不是历史整项目的原始耗时。

输入主词条、可用圣遗物等筛选仍由原有入口完成。结果保证只针对传入算法的候选域。部位没有任何候选时继续沿用部分配装行为，结果该部位为 `None`；套装数量必须由实际存在的物品满足。`Set22(s, s)` 需要四件同套装；`Set22(a, b)` 不受参数顺序影响。

## 前 k 结果约定

[ResultRecorder](../mona_wasm/src/applications/optimize_artifacts/algorithms/common.rs) 统一维护有限评分的前 k 个不同配装：

- 按分数降序；分数完全相同时，按花、羽、沙、杯、冠的 ID 元组升序。零和负零视为同分，不对其他分数取整或量化。
- 使用完整 ID 元组去重，不用单个哈希值代替身份；支持 ID 为 0 与缺部位。
- 收满 k 个不同结果前，剪枝门槛为负无穷。`k = 0` 直接返回，不计算目标函数。
- 忽略 NaN 和正负无穷评分；零分最优结果的展示比例为 1，避免 `0 / 0`。
- 堆与集合只保存当前前 k 项，不保存所有访问过的组合。候选不可能入选时不再先压堆再弹出。

已满池时，分组搜索同时比较分数估值和后续部位的最小 ID 元组。同分分支只有在 ID 排名仍可能更好时才继续。最小 ID 可以来自一个实际不可行的组合，因为放宽可行域得到的 ID 下界仍然保守。此规则不把原来的分数估值变成经过证明的上界。

## 分组搜索的修正

排序使用浮点数比较及稳定的次级键，移除 `-score as usize` 导致正权重全部归零的问题。单件权重分数只预计算一次，包含强化等级不同的主词条。收益探测保留收益大小与正负号，补充固定攻击、生命、防御，不再把所有正收益都写成 1。

超级圣遗物对同组主词条也取最大值，而非取第一件的值。所有路径均在搜索开始前复制敌人并应用一次 Buff 敌人修正。

套装遍历拆成互不重叠的四类：至少四件同套装、两个不同套装各至少两件、仅一个套装出现两至三件、没有重复套装。每个重复套装固定其在部位顺序中的前四次或前两次出现，其余出现只能位于这些位置之后。递归在评分完整组合前检查此前缀条件，避免同一配装沿多个掩码反复评分；不需要一个随访问量增长的全局已访问集合。

## 可靠性边界

**纯枚举**不依赖评分单调性，不删除凸包内部点，不做普通 Pareto 淘汰，不按词条预筛选。对于确定性的有限目标评分，完成遍历后返回当前约束下前 k 个不同配装，可用来验证新的上界与专用算法。若候选少于 k，则返回全部可行结果。大候选域仍可能耗时或超时。

**分组剪枝**仍是启发式方法。词条分别取最大值并不能证明任意非单调目标、属性转换、原始物品元数据条件、自定义 DSL 或套装效果下的分数和属性约束上界。收益排序也会探测虚拟配装；依赖原始物品的自定义目标应使用纯枚举。`accuracy_factor = 1` 不代表通用精确保证；较小值只是更激进的估分折减，不是误差或最优性证书。

凸松弛 / 支持函数上界、暴击率分组、属性图模板与稠密求解仍未接入生产路径。后续接入需要明确的目标能力声明与保守上界证明，并用枚举基准核对分数、完整前 k ID、约束、配置和浮点边界。不能只看最优分数或一次模板输出一致。

## 复用求解结果与属性查询

约束检查和目标评分原先会重复求解同一张属性图。新增可选的 `TargetFunction::target_from_solved`，只在已审计的最大攻击力、安柏默认和那维莱特默认目标启用；其他目标默认返回 `None`，继续调用原 `target`。新路径同时用于真实组合和分组估值，保持原始圣遗物与敌人上下文。未通过约束时不评分。

这个能力仅表示可以复用当前求解结果，不表示目标线性、单调，也不授权跨组合缓存。会在评分前添加技能效果或修改属性图的目标必须另外审计。

`AttributeNode::for_each_parent` 提供不创建临时列表的查询方式，原 `get_parents` 接口仍保留。简单属性求解器和结果查询使用新接口；同一条边的两个输入节点相同时复用查询值。父节点访问顺序、浮点加法起点、同优先级读取旧快照，以及静态边减去旧贡献再重算的顺序均保持不变。测试用冻结的旧求解器逐位核对，包括通配属性、抵消、负零和非有限值。

## 相同已求解面板的评分缓存

[score_cache.rs](../mona_wasm/src/applications/optimize_artifacts/algorithms/score_cache.rs) 在一次优化调用内复用完全相同的数值输入。每个真实组合仍构建并求解属性图、检查约束、保留自己的圣遗物 ID；只省略可复用的目标评分。它可以与纯枚举、分组剪枝组合使用，分组的虚拟估值也走同一接口，不改变原估值的可靠性边界。

新增的 `TargetFunction::can_memoize_solved_score` 默认关闭，比求解结果复用要求更强：快速评分必须是纯函数，只读取完整数值节点表、当前角色 ID，以及本次固定的角色、武器、敌人和目标配置，不能读取原始物品、属性来源或角色状态元数据。经调用链核查，当前仅安柏默认和那维莱特默认启用；最大攻击力评分很便宜，不启用缓存，其他角色与 DSL 也保持关闭。

键包含完整节点身份及 `f64::to_bits()`，排序消除节点表遍历顺序的差异，完整键比较处理哈希碰撞。负零、缺失节点和显式零、最后一位浮点差异均不混同。不对属性取整，也不假定相同词条列表一定得到相同的浮点求解结果。不同请求的敌人、Buff 或配置不会共享缓存。

容量与回退策略：

- 最多 256 项，每项最多 256 个节点，累计键载荷最多 512 KiB，另有受条目数限制的哈希表开销；达到条目或载荷限制时清空旧项，再存当前项。
- 连续 64 次未命中，或每个 128 次查询窗口命中率低于 25%，本次请求永久停用缓存并释放已保留内存。此阈值是开销控制策略，不保证所有输入都加速；前期重复很少时，也可能放弃后期潜在收益。
- 节点表过大、快速评分返回 `None` 时停用。`None` 仍回退原目标；NaN 和无穷评分不缓存。

这一步没有减少属性图求解次数，也没有将搜索复杂度降为等价类数量。它验证了“不同物品组合共享评分，但保留全部前 k 身份”的一部分；求解前压缩仍需要下文所述的额外证明。

## 可重复的对照基准

```sh
cargo run --release --manifest-path mona_wasm/Cargo.toml --features optimizer-legacy --bin bench_single_optimizer -- --target amber --per-slot 6 --k 100 --repeats 5
```

`--target` 可选 `max_atk`、`amber`、`neuvillette`。默认比较九条路径：新枚举、新分组各自关闭复用、只复用求解结果、再加评分缓存，及旧分组、旧 AStar、旧枚举。每条路径预热一次，再记录每次耗时、返回数量、原目标调用次数、实际快速评分调用次数、完整前 k ID 和分数是否逐位匹配。缓存命中不会计为一次实际评分调用；最大攻击力的缓存能力关闭，两条复用路径行为相同。

`--input <path>` 可替代生成数据，文件格式为 Rust `Vec<Artifact>` 的 JSON（`id`、`slot`、`set_name`、`level`、`star`、`main_stat`、`sub_stats`），不直接接受 Mona/YAS 网页导出格式。为避免意外穷举过大仓库，基准最多接受一百万个组合。输入文件只读，不访问浏览器账号或修改导入数据。

`--copies 1..8` 将每件输入物品复制若干份并分配不同 ID，默认为 1；例如 `--per-slot 3 --copies 2` 仍是每部位 6 件，可观察部分物品属性重复的情况。`--profile rolls` 为默认构造数据；`--profile distinct` 向充能词条加入极小的部位编码扰动，刻意制造低复用面板，测试停用缓存的开销。这是人工压力数据，不代表合法词条分布；`--profile distinct` 不与 `--input` 混用。

## 等价组合压缩的研究结论

源码核查表明 `ArtifactList::apply` 聚合词条和套装数量，不读取物品 ID；但 `TargetFunction::target` 可以读取原始圣遗物，因此不能全局合并同属性物品。这个方向仍有价值：每部位若有 `n_i` 件、但只有 `m_i` 种经证明等价的属性形式，昂贵评分次数有机会由 `∏n_i` 降到 `∏m_i`，再展开需要的 ID 组合。

前 k 必须保留等价类里的所有物品身份。同分块按花到冠的 ID 字典序展开，单块至多需要前 k 个 ID 组合；不能只保留一个代表物品。实现前还要明确：目标不依赖 ID、保留元数据及词条顺序的范围、求解的确定性、位级浮点结果是否相同。当前的两个评分能力接口不满足求解前等价性证明，因此没有把物品等价类压缩自动应用到角色或 DSL。已接入的缓存只在求解后比较完整数值结果。

同理，目标叫“最大攻击力”并不证明从物品到最终攻击力的整体映射线性：武器、Buff、套装和属性转换仍可能改变依赖结构。直接套用凸包顶点淘汰仍不成立。下一步需要单独的依赖与上界能力声明，当前三种目标的快速评分入口可以减少这类新算法每次调用的成本。

## 验证

```sh
cargo test --manifest-path mona_wasm/Cargo.toml --lib optimize_artifacts
cargo test --manifest-path mona_wasm/Cargo.toml --features optimizer-legacy --lib optimize_artifacts
cargo test --manifest-path mona_core/Cargo.toml --lib attribute::
npm run build:wasm
npm run test:project:typecheck
npm run test:project:unit
npm run test:project -- --suite single-optimizer
```

回归测试包括独立笛卡尔积全排序对照、同分与负分、零 k、重复 ID、缺部位、不可行套装约束、套装参数顺序、混合强化等级、非单调目标、Buff 敌人修正，以及安柏和那维莱特真实目标的小域对照。另枚举五种套装的全部 `5^5 = 3125` 个部位布局，在不同套装约束下验证无漏分区、无重叠分区。

评分缓存另覆盖逐位键、不可见属性维度、当前角色身份、容量和字节预算回收、低命中停用、非有限值、缺失快速路径回退、不同请求隔离，以及依赖原始物品 ID 的目标默认绕过缓存。重复属性用例同时核对纯枚举、分组和完整排序的前 k；包括 k 大于可行组合数时保留全部不同 ID。

`single-optimizer` 浏览器场景覆盖版本 3/4 预设的算法名称、无算法字段预设、导入导出、重新加载、账号切换、计算器状态恢复，以及页面选项和保存。实际 Worker 使用 1024 个同分组合验证三个旧标识返回一致的前 100 套不同 ID，避免只验证页面文案。

构造的 1024 个同分组合取前 100 用例中，完整组合评分从遍历全部 1024 个减少到 100 个，返回 ID 与全排序相同。这是同分排名剪枝的回归证据，不是实际账号或完整浏览器耗时加速倍数。测试未证明分组估值在所有角色、武器、套装和 DSL 上安全。
