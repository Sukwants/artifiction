# 代码审查文档

本文档为项目代码审查说明。对于人类，如需检查新增内容，可以参考以下说明；对于 AI，请严格按照以下说明进行审查。

## 基本原则

代码审查过程中**不得修改任何项目文件**，包括自动格式化、自动修复、自动重构等行为。如发现需要修改的内容，仅进行记录并输出审查结果。

除 `/tmp/` 下的审查结果外，不得创建、删除或修改任何文件。

审查过程中如缺少必要信息（如原始数据文件不存在、文档缺失、对象无法确定等），应立即停止并询问，不得自行推断。

---

## 审查流程

AI 必须严格按照以下顺序执行，不得跳过、合并或提前执行后续步骤。

### 第一步：获取修改文件列表

首先仅获取本次修改涉及的文件名。

此阶段：

* 仅允许获取修改文件列表。
* 不允许读取任何文件内容。
* 不允许读取完整 diff。
* 不允许提前分析代码。

如果修改文件中包含图片、视频、字体、二进制文件等资源文件，应直接忽略。

---

### 第二步：确定审查对象

根据文件名筛选需要重点审查的文件。

需要重点审查：

* 角色
* 武器
* 圣遗物
* 计算函数
* Buff

其他文件仅进行简要检查或直接跳过。

---

### 第三步：逐文件审查

必须按文件逐个完成。

对于每个文件：

1. 仅读取当前文件。
2. 根据需要读取对应原始数据文件。
3. 根据需要读取对应文档。
4. 完成当前文件全部审查。
5. 输出当前文件结果。
6. 再继续下一个文件。

不得：

* 同时读取多个待审查文件。
* 提前读取下一个文件。
* 获取整个项目的完整 diff。
* 获取整个仓库全部上下文。

---

## 原始数据

代码审查中需要阅读原始数据文件，一般位于：

```
/prompt/{name}/{name}_{lang}.json
```

如未找到，请直接询问。

如需要理解完整逻辑，请阅读：

```
mona_docs/src/index.md
```

除非确有需要，不应阅读无关文档。

---

# 书写审查

在书写审查阶段，需要阅读并了解当前审查代码对应的原始数据文件，并根据原始数据文件内容，按照检查清单逐项检查代码书写是否正确。

检查清单位于：

```
mona_docs/src/review/checklist.md
```

必须完整遍历所有检查项，不得省略。

不得因代码看起来正确而跳过检查项。

## 输出

对于每个未通过或存在疑问的检查项：

生成一个结果文件至：

```
/tmp/
```

内容应包括：

* 文件
* 对象
* 检查项
* 问题描述
* 对应代码位置
* 建议
* 人类回复（留空）

---

# 逻辑审查

逻辑审查需要完整理解：

* 原始对象
* 数据
* 实际描述
* 代码实现

确认代码逻辑是否与原始对象保持一致。

重点检查：

* 原始文本理解错误
* 漏实现
* 多实现
* 条件遗漏
* 数值错误
* Buff、生效条件、持续时间、层数等逻辑是否一致
* 是否存在逻辑漏洞

不得仅根据代码推断逻辑，必须与原始数据进行逐项对照。

## 输出

如发现可能存在逻辑问题，同样生成结果文件至：

```
/tmp/
```

内容包括：

* 文件
* 对象
* 原始逻辑
* 当前实现
* 差异说明
* 风险分析
* 人类回复（留空）

---

# 审查要求

AI 应尽量减少上下文占用。

除当前正在审查的文件及其必要依赖外，不应主动读取其他文件。

不得一次获取整个项目、整个 diff 或所有修改内容。

如需要额外上下文，应在当前文件完成后再决定是否读取，并仅获取最小必要范围。

整个审查完成后，再统一输出总结。
